import { Aside } from '@astrojs/starlight/components';

<Aside type="danger" title="Problem">
  You need to skip tests under certain conditions or explicitly fail tests when
  requirements aren't met.
</Aside>

<Aside type="tip" title="Solution">
  Use `utils.skip()` and `utils.fail()` in your hooks.
</Aside>

## Skipping Tests

Use `utils.skip()` when a test cannot run due to missing preconditions.

### Reason to Skip

- Required resources cannot be created
- Prerequisites are not met
- Test is not applicable for certain conditions

### Basic Usage

```typescript
import { beforeEach } from '@thymian/hooks';

export const seed = beforeEach(
  'GET /launches/{id} -> 200 (application/json)',
  async (request, ctx, utils) => {
    const response = await utils.request(
      'POST /launches (application/json) -> 201 (application/json)',
      {
        body: {
          missionName: utils.randomString(10),
          launchDate: '2026-12-31T00:00:00Z',
          rocketType: 'Falcon9',
        },
        headers: { 'content-type': 'application/json' },
      },
    );

    // Skip if resource creation failed
    if (response.statusCode !== 201) {
      utils.skip('Cannot create required launch resource');
    }

    request.pathParameters.id = response.body.id;
  },
);
```

### Skip with Details

Provide detailed information about why the test was skipped:

```typescript
if (response.statusCode === 503) {
  utils.skip(
    `Service unavailable (status ${response.statusCode}). Cannot proceed with test.`,
  );
}
```

## Failing Tests

Use `utils.fail()` when a test should explicitly fail due to invalid conditions.

### When to Fail

- Setup produces unexpected results
- Resources are in an invalid state
- Critical preconditions are violated
- Data validation fails

### Basic Usage

```typescript
import { beforeEach } from '@thymian/hooks';

export const seed = beforeEach(
  'GET /launches/{id} -> 200 (application/json)',
  async (request, ctx, utils) => {
    const response = await utils.request(
      'POST /launches (application/json) -> 201 (application/json)',
      {
        body: {
          missionName: utils.randomString(10),
          launchDate: '2026-12-31T00:00:00Z',
          rocketType: 'Falcon9',
        },
        headers: { 'content-type': 'application/json' },
      },
    );

    // Fail if creation returned wrong status
    if (response.statusCode === 200) {
      utils.fail(`Expected 201 Created, got ${response.statusCode}`);
    }

    // Fail if response body is invalid
    if (!response.body.id) {
      utils.fail('Created launch has no ID field');
    }

    request.pathParameters.id = response.body.id;
  },
);
```

## What Happens When You Skip or Fail?

### Skip

```typescript
utils.skip('Resource unavailable');
```

**Result:**

- Test is marked as **skipped**
- Remaining hooks do not execute
- Test does not count as failure
- Test report shows skip reason

**Output:**

```
GET /launches/123
  ⊘ Skipped: Resource unavailable
```

### Fail

```typescript
utils.fail('Invalid response structure');
```

**Result:**

- Test is marked as **failed**
- Remaining hooks do not execute
- Test counts as failure in report
- Test report shows failure reason

**Output:**

```
GET /launches/123
  ✗ Failed: Invalid response structure
```

## Technical Details

Both `skip()` and `fail()` throw special errors that are caught by the hook runner:

```typescript
// These throw errors internally
utils.skip('message'); // Throws SkipError
utils.fail('message'); // Throws FailError
```

<Aside type="note">
  These methods never return. TypeScript recognizes them as `never` return type.
</Aside>

## Alternatives

### Returning early

For simple conditional logic, return early without skipping:

```typescript
export const seed = beforeEach(
  { path: '/launches/{id}' },
  async (request, ctx, utils) => {
    // The 404 case wants a resource that does not exist, so leave it alone.
    if (ctx?.thymianRes.statusCode === 404) {
      return;
    }

    // Otherwise, do the setup.
  },
);
```

This does not skip the test case; it just skips the hook's own work. Often the
better move is to narrow the target instead, so the hook never runs there:
`beforeEach({ path: '/launches/{id}', statusClass: '2XX' }, …)`.

### Using Assertions

For validation in afterEach hooks, consider using `utils.assertionFailure()` instead of `utils.fail()`:

```typescript
export const assertShape = afterEach(
  'GET /launches/{id} -> 200 (application/json)',
  (response, ctx, utils) => {
    const body = JSON.parse(response.body ?? '{}');

    if (!body.id) {
      utils.assertionFailure('Missing ID field', {
        expected: 'id field present',
        actual: 'id field missing',
      });
    }
  },
);
```

**Difference:** `assertionFailure()` records a failed assertion but allows other validations to continue. `fail()` stops execution immediately.
